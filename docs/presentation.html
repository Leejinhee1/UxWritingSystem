03 / 각 레이어별 설명

L1Voice (브랜드 성격)

관리 항목 (실제 데이터)

페르소나 똑똑한 금융생활 도우미 북극성 "똑똑한 소비습관을 위한 서비스" 성격 따뜻한, 쉬운, 구체적인, 안심되는, 가족적인 안티 성격 전문적인, 사무적인, 차가운, 형식적인

Voice는 브랜드당 1개만 존재. 전체 검수의 톤 기준.

각 필드가 하는 일

페르소나
AI에게 "너는 이런 사람이야"라고 알려줌. 수정안의 말투를 결정하는 기본 정체성.
북극성
브랜드가 지향하는 한 문장. 수정안이 이 방향에서 벗어나지 않게 함.
성격 (traits)
AI가 수정안을 만들 때 반영할 톤. "따뜻한"이면 딱딱한 문장을 부드럽게 고침.
안티 성격 (anti-traits)
이렇게는 쓰지 말라는 가드레일. 수정안이 이 방향으로 빠지지 않게 방지.

03 / 각 레이어별 설명

L2Writing Principles (글쓰기 원칙)

관리 항목 (능동태+권유형 예시)

원칙 이름 능동태 + 권유형 설명 능동태와 권유형 문장을 사용한다 severity warning Do "신청해보세요" Don't "신청이 필요합니다"

잡초뽑기 원칙은 추가로 weeds(잡초 단어 목록)를 관리
이 외에도 구체적 숫자, ~해드려요 패턴 등을 같은 구조로 관리

각 필드가 하는 일

원칙 이름 + 설명
AI에게 "이런 원칙이 있다"고 알려줌. 위반 판단의 근거가 되는 텍스트.
Do / Don't
AI가 좋은 예/나쁜 예를 참고해서 비슷한 패턴을 잡아냄. 수정안의 방향을 잡는 기준.
severity
위반의 심각도. error면 반드시 수정, warning이면 권장, info면 알림만.
weeds (잡초뽑기 전용)
잡초 단어 목록. 이 단어들이 불필요하게 쓰였는지 AI가 맥락을 보고 판단.

03 / 각 레이어별 설명

L3Grammar & Mechanics (문법/형식)

관리 항목 (날짜 형식 예시)

규칙 이름 날짜 형식 설명 M월 D일 (요일) 형태 severity warning Do "4월 25일 (금)" Don't "4/25", "2026.04.25"

종결어미 통일 규칙은 추가로 detect, replacements, exception을 관리
이 외에도 숫자 표기, 이모지 규칙 등을 같은 구조로 관리

각 필드가 하는 일

규칙 이름 + 설명 AI
AI에게 "이런 문법 규칙이 있다"고 알려줌.
Do / Don't AI
올바른 형식과 틀린 형식을 참고해서 위반을 잡고 수정안 생성.
severity
error = 반드시 수정 · warning = 권장 · info = 알림만
detect + replacements + exception (종결어미 전용) 규칙 기반
정규식으로 패턴을 자동 감지(detect) → from→to로 자동 치환(replacements).
exception: 라벨/버튼 등 적용 제외 대상 지정.

03 / 각 레이어별 설명

L4Component Patterns (UI 요소별 패턴)

관리 항목 (error_message 예시)

ui_type error_message text_type sentence (문장형) 톤 공감하되 가볍지 않게 패턴 규칙 공감 + 해결책 skipOption (없음) Do "잠시 문제가 생겼어요. 다시 시도해주세요." Don't "오류가 발생했습니다" 메모 (선택, 내부 참고용)

button, heading, empty_state, label 등 UI 유형마다 같은 구조로 관리

각 필드가 하는 일

ui_type + text_type
테스트 시 선택하는 UI 유형과 1:1 매칭. text_type은 문장형/명사형 등 AI의 분류 판단 기준.
톤 + 패턴 규칙 + Do/Don't
"이 유형은 이런 말투로, 이런 구조를 갖춰야 해"라고 AI에게 지시. 위반 판단과 수정안의 핵심 근거.
skipOption — 가장 중요
이 UI 유형에서 건너뛸 규칙을 지정.
button → 종결어미/잡초뽑기 skip · label → ALL skip (L5만 검사)

03 / 각 레이어별 설명

L5Word List (용어집)

관리 항목 (하나카드 예시)

공식 용어 하나페이 정의 하나카드에서 제공하는 어플리케이션 공식 명칭 틀린 표현 원큐페이, 하나pay

각 필드가 하는 일

공식 용어 (term)
우리 서비스에서 써야 하는 정식 명칭. 수정안에 이 단어가 들어감.
정의 (definition)
이 용어가 무엇인지 설명. 레퍼런스 탭에서 팀원이 확인할 수 있음.
틀린 표현 (aliases) 규칙 기반
이 단어가 입력에 있으면 AI 없이 코드가 즉시 위반으로 잡음.
label이든 body든 무조건 검사 (UI 유형 무관)

03 / 검수 시스템 동작 방식

검수 시스템 동작 방식

2레이어 하이브리드 — 규칙 엔진 + AI를 결합

1단계: 규칙 기반 Deterministic
L3 Grammar — detect 패턴 정규식 매칭
L5 용어집 — aliases 문자열 매칭
정확도 100% · 비용 0원
↓
2단계: AI 기반 gpt-4o
L1 Voice + L2 Principles + L3 Grammar + L4 Patterns
1단계 결과 중복 제거 · 정확도 ~80%
↓
3단계: 결과 병합
violations + suggestions + combined_suggestion + pass/fail
